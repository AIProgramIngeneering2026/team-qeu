# Правила работы над проектом

## 1. Ветки

- `main` — основная стабильная ветка проекта.
- Для каждой задачи создаётся отдельная ветка.
- Названия веток: `feature/<название>`, `fix/<название>`, `docs/<название>`, `test/<название>`.
- Изменения в `main` вносятся только через Pull Request.

Примеры: `docs/requirements`, `feature/job-model`, `fix/validation`.

## 2. Коммиты

- Каждый коммит должен содержать логически завершённое изменение.
- Сообщения коммитов должны быть короткими и понятными.
- В сообщении указывается, что было добавлено или исправлено.

Примеры:
- `p1 — описание проекта`
- `p1 — требования и сценарии`
- `feat — добавлена модель Job`
- `fix — исправлена проверка параметров`

## 3. Pull Requests и Review

- Каждая задача выполняется в отдельной ветке и оформляется через Pull Request.
- В описании PR указывается, что изменено, и добавляется ссылка на соответствующий Issue, если он существует.
- Перед слиянием проверяются изменения, соответствие требованиям и результаты доступных проверок.
- Если в команде несколько участников, Review выполняет другой участник. Замечания и вопросы оставляются в комментариях к конкретным изменениям.
- Пока в команде один участник, автор самостоятельно проверяет изменения перед слиянием PR.
- После проверки и устранения замечаний PR сливается в `main`.

## 4. Definition of Done

Задача считается выполненной, если:

1. Реализованы все требования и критерии приёмки соответствующего Issue.
2. Изменения проверены на корректность.
3. Для программного кода добавлены или обновлены необходимые тесты, когда это применимо.
4. Все доступные автоматические проверки проходят успешно.
5. Документация обновлена при необходимости.
6. Изменения внесены в `main` через Pull Request.
7. Соответствующий Issue закрыт после завершения работы.

## 5. Организация работы

- Все задачи фиксируются в GitHub Issues и назначаются ответственным участникам.
- Перед началом работы выбирается Issue и создаётся отдельная ветка.
- При добавлении новых участников задачи распределяются между ними.
- Правила работы могут уточняться по мере развития проекта.
