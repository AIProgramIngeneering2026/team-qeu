# Проверка контрактов колодой К1–К10 — Qeu (P2)

**Дата:** 2026-11-15  
**Объект проверки:** проектируемый «Сервис выполнения заданий». Это проверка спецификаций, а не результаты запуска реализованного API.

## Проверка колодой

| Карта | Ответ контракта и ссылка на решение |
|---|---|
| **К1 — Двойной клик** | Если клиент отправил два одинаковых `POST /jobs` с одним `Idempotency-Key`, создаётся **одна** Job: первый ответ `202` (`created`), повторный — `200` с прежним `id` и актуальным статусом. Без ключа могут появиться две Job — это осознанное ограничение. [OpenAPI: POST /jobs](api/openapi.yaml#L21-L43), [ADR-0002](adr/0002-idempotency-key.md#L13-L24). |
| **К2 — Ответ потерялся** | Клиент повторяет запрос с **тем же** `Idempotency-Key` и теми же данными: `200` и прежний `id`; затем `GET /jobs/{id}`. Если исходный запрос был **без ключа** и клиент потерял `id`, надёжного поиска созданной Job контракт не обещает. [OpenAPI](api/openapi.yaml#L21-L43), [ADR-0002](adr/0002-idempotency-key.md#L35-L41). |
| **К3 — Неизвестная операция** | `POST /jobs` возвращает `400` с `ApiError.error.code = UNKNOWN_OPERATION`, `field = operation`. Job **не создаётся**. [OpenAPI: ошибка 400](api/openapi.yaml#L89-L102), [Tool: валидация](tool-contract.md#L58-L67). |
| **К4 — Кривые параметры** | Отсутствующее поле, неправильный тип, недопустимое значение (в том числе деление на ноль) → `400`, `ApiError.error.code = INVALID_PARAMS`, `field` указывает неверный параметр. Job **не создаётся**. [OpenAPI](api/openapi.yaml#L103-L116), [Tool](tool-contract.md#L71-L102). |
| **К5 — Воскрешение** | Повторный запуск существующей Job **не поддерживается**: есть только создание нового Job через `POST /jobs` и чтение `GET /jobs/{id}`. Состояния `done` и `failed` терминальные, `GET` их не изменяет. Новый запрос без прежнего ключа может создать **новую** Job с другим `id`, но не перезапускает старую. [OpenAPI](api/openapi.yaml#L15-L24), [диаграмма состояний](architecture.md#L80-L107), [ADR-0001](adr/0001-background-jobs.md#L15-L23). |
| **К6 — Отмена** | **Сознательно не поддерживается** в первой версии: нет операции отмены и состояния `canceled`. После начала внешнего действия нельзя обещать его откат; система не предоставляет ложной гарантии отмены. [Набор операций OpenAPI](api/openapi.yaml#L15-L16), [диаграмма Job](architecture.md#L80-L103), [ADR-0001: границы внешних эффектов](adr/0001-background-jobs.md#L34-L40). |
| **К7 — Огромный вход** | При превышении общего лимита тела HTTP-запроса API отвечает `413` с `ApiError.error.code = REQUEST_TOO_LARGE`, Job не создаётся. Для текста дополнительно установлен максимум **10 000 символов**, для `http.get.resource` — **255**; нарушения параметров → `400 INVALID_PARAMS`. **Открытое уточнение:** числовой предел общего тела HTTP пока не указан в OpenAPI, его следует зафиксировать до реализации. [OpenAPI: 413](api/openapi.yaml#L128-L137), [схемы](api/openapi.yaml#L253-L287). |
| **К8 — Чужой или несуществующий id** | Неверный формат UUID → `400 INVALID_ID`; отсутствующий UUID → `404 JOB_NOT_FOUND`; существующий UUID → `200` с Job. **Ограничение:** текущий прототип не предусматривает учётные записи и разграничение доступа, поэтому изоляция данных разных пользователей **не гарантируется**. Для многопользовательского развёртывания потребуются авторизация и пересмотр контрактов. [OpenAPI: GET](api/openapi.yaml#L142-L223), [ADR-0002: граница прототипа](adr/0002-idempotency-key.md#L24-L24), [пересмотр](adr/0002-idempotency-key.md#L43-L45). |
| **К9 — Перезапуск сервера** | Job хранится постоянно; перезапуск не должен уничтожать сведения о Job. Но для задач, оставшихся в `running`, **автоматический повтор не обещается**: внешний эффект мог уже произойти. Восстановление/сверка таких задач требует отдельной политики; их нельзя автоматически переводить обратно в `created`. [ADR-0001: решение](adr/0001-background-jobs.md#L15-L23), [цена и ограничение](adr/0001-background-jobs.md#L34-L40), [состояния](architecture.md#L80-L107). |
| **К10 — Внешний сервис** | HTTP-адаптер ограничивает ожидание и число безопасных повторов, проверяет статус и формат ответа. После окончательной ошибки Job → `failed` с `Job.error.code` (`PROVIDER_TIMEOUT`, `PROVIDER_BAD_RESPONSE` или `PROVIDER_REQUEST_FAILED`); `GET /jobs/{id}` возвращает `200` с Job в состоянии `failed`. Если эффект на стороне провайдера неопределён, автоматический повтор без гарантий безопасности не выполняется. [Tool](tool-contract.md#L121-L140), [OpenAPI: failed](api/openapi.yaml#L189-L199), [ADR-0001](adr/0001-background-jobs.md#L34-L40). |

**Итог:** для каждой карты указано предусмотренное поведение либо осознанное ограничение. Не поддерживаются отмена, многопользовательская изоляция и автоматическое восстановление неоднозначного внешнего действия. Перед реализацией необходимо уточнить числовой лимит HTTP-тела; это не следует выдавать за уже согласованное ограничение.

## Что предложил ИИ

**Использованная модель:** ChatGPT (GPT-6).  
**Промпт:**

> Изучи контракт сервиса выполнения заданий Qeu (`docs/api/openapi.yaml`, `docs/tool-contract.md`, `docs/architecture.md`, два ADR) и карты К1–К10 из `tasks/p2_poker/README.md`. Сыграй атакующего и найди **ещё три** конкретных пограничных случая, которые не полностью определены этими контрактами. Для каждого укажи вход, ожидаемое поведение, место пробела и возможную поправку. Не считай проект реализованным и не придумывай уже существующие гарантии.

| Дополнительная находка ИИ | Решение команды и обоснование |
|---|---|
| **А1. `http.get` с `resource = "//internal"`.** Нынешний regex допускает две начальные косые черты. При небезопасном соединении с базовым URL адаптер может изменить целевой хост. | **Принято к уточнению контракта.** Необходимо запретить абсолютные/схемно-относительные пути и перенаправления на иной хост, указать `400 INVALID_PARAMS`, `field = params.resource`. Текущий контракт [пока разрешает такой ввод](api/openapi.yaml#L270-L290); до исправления нельзя считать риск закрытым. |
| **А2. Провайдер возвращает очень большой ответ с HTTP 200 и синтаксически корректным JSON.** Проверка формата не ограничивает объём загрузки. | **Принято к уточнению.** Нужно установить предел размера *внешнего ответа* в HTTP-адаптере и отображать его превышение как контролируемую ошибку Job (`failed`), а не падение процесса. Текущий [контракт HTTPTool](tool-contract.md#L121-L140) описывает timeout/формат, но не предел ответа. |
| **А3. Повтор `Idempotency-Key` при численно эквивалентных, но текстуально разных JSON-числах (`1` против `1.0`).** Указана нормализация порядка полей, но не правила нормализации чисел. | **Принято к уточнению.** До реализации надо зафиксировать канонизацию типов/чисел либо явно считать эти запросы разными и возвращать `409` для одного ключа. Сейчас в [ADR-0002](adr/0002-idempotency-key.md#L15-L24) определена нормализация запроса, но не этот крайний случай. |

**Статус предложений ИИ:** это обнаруженные уточнения, **ещё не внесённые** в OpenAPI/Tool/ADR. Они отмечены явно, чтобы не выдавать проверку документации за готовую реализацию. Перед финальной сдачей P2 желательно согласовать их с соответствующими контрактами отдельными правками.
